### 3A.2. Как читы технически взаимодействуют с игрой

Любой Dota 2 чит — это программа, которая:

1. **Запускается отдельным процессом** до или после Dota 2.
2. **Внедряется (инжектится) в процесс игры** через DLL-injection (manual mapping = обход VAC-сканов модулей).
3. **Читает память игры** через интерфейсы Source 2 engine (`Source2EngineToClient001`, `IClientEntityList`, `CEngineClient`, схема Source 2).
4. **Хукает функции рендера** (`VPanelWrapper::PaintTraverse` в Source 2) — для отрисовки элементов чита поверх игры.
5. **Имитирует ввод** (`PrepareUnitOrders` для отдачи команд героем — клики, кастов, движения).
6. **Получает данные о ����������остоянии матча** (HP врагов, CD скиллов, нетворс, позиции) через структуры памяти, обновляемые сервером.
7. **Применяет скрипты в реальном времени** — на каждом игровом тике (~30 раз в секунду) проверяет условия и реагирует.

> **Важно для контента:** ВСЕ функции чита работают только с теми данными, которые **уже есть в памяти твоего клиента**. Если сервер Valve не отправил данные — чит их не покажет (это критично для понимания «нового» MapHack — см. раздел 3A.5).
