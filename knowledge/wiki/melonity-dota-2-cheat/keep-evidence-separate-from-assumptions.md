## Keep evidence separate from assumptions

An interface screenshot proves that a control was displayed at one moment. It does not prove that the control is enabled for every hero, that its data is current, or that the product is available on the build you are running. Treat each screenshot as a prompt for a live-listing question.

Support answers should be specific enough to save. Ask for the supported build, required Windows version, activation sequence and documented removal path. A clear “not supported right now” is more useful than a broad “everything works” reply. Save the answer with the date because a patch can invalidate it.

Check the boundary between account access and system access. The Melonity account should handle plan and download information; it should not require a Steam login. An installer should identify what it changes and how to undo it. These checks make onboarding easier to review without turning this article into an unverifiable endorsement.

Feature labels need a current explanation, not a recycled clip.

A product-level review can describe the interface and the current support window.
