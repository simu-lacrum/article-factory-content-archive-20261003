**Dota 2 cheat features** are easier to evaluate when they are grouped by the job they perform. Product pages often place ESP, maphack, combo scripts, last-hit tools and cosmetic changes in one list. A useful review asks what information a function uses, what action it changes and what happens after a game update.

This guide describes the categories without promising that any third-party program is safe or undetected. Valve treats third-party modifications that provide an unfair advantage as cheating, and a feature can stop working or become detectable without warning.

## Visual and information features

Visual modules aim to make game state easier to read. Common labels include range indicators, cooldown panels, ward notifications and ESP. Some can be based on information already visible to the player; others claim to expose data concealed by fog of war. The label alone does not tell you which is being used.

A practical listing should explain where an indicator appears, whether it is configurable and which heroes or entities it covers. “Full vision” is not a specification. ## Targeting and cast assistance

Targeting aids may select a nearby enemy, prioritize a configured unit or draw a suggested cast position. Prediction features try to account for movement and projectile travel. Their result still depends on latency, vision, spell behavior, immunity, dispels and the player's configuration.

A cast assistant cannot know every strategic exception. Automatically using a disable on the first valid target may waste it before a more important enemy appears. Fast execution is not the same as correct decision-making.

## Hero scripts and combo logic

Hero scripts connect conditions to actions. A script might order several abilities and items, react to a channel, or apply a defensive item when a condition is met. The quality depends on the logic, supported hero build and how well the author handles edge cases.

Patch changes can invalidate item names, timings, cast ranges and talent assumptions. ## Farming and utility tools

Utility labels can include last-hit indicators, stack timers, rune reminders, inventory panels or camera controls. Some are informational; some automate an input. Their value varies by role. A support player may care about ward and enemy-item context, while a carry may focus on farming and target priorities.

Do not count similar labels as separate functions. Five toggles for the same overlay are not five independent systems. Look for concrete screenshots, dated demonstrations and exclusions.

## Official rules outweigh vendor claims

[Steam's official VAC guidance](https://help.steampowered.com/en/faqs/view/571A-97DA-70E9-FF74) says third-party modifications that give one player an advantage are classified as cheats. It also warns users to be careful with scripts and custom skins. That policy should frame every feature review.

## Turn a feature list into testable questions

Rewrite each marketing label as a result you could observe. “Smart target selection” becomes: which units are eligible, how are priorities ordered, and when does the module stop? “Ward tracker” becomes: which events create a marker, how long does it remain and can it show an estimate as exact? Concrete questions expose missing documentation quickly.

Use the same method for screenshots and videos. Note the recording date, visible Dota build, hero, mode and configuration. A polished clip can establish that an interface existed; it cannot establish today's compatibility, every claimed function or the absence of enforcement risk.

Finally, rank features by frequency and consequence. A small reminder used every match may have more practical value than a spectacular automation module for one hero. Conversely, a hidden-information function may add much more account risk than its occasional value justifies. This priority list keeps the evaluation tied to use rather than page length.
