# Foxhole Artillery Coordination: The Information Checklist Before Every Salvo

Foxhole artillery coordination breaks when a correct input arrives late, two crew members use different reference points, or an old target call survives into a new cycle. Reliability starts before any action: one source, one timestamp, explicit roles, a repeated confirmation, and a reset that clears stale information.

## Accuracy starts before the shot

The crew succeeds or fails on information flow. A range value without a reference point is incomplete. A direction without a timestamp may already be stale. A correct call that nobody repeats back can still be heard incorrectly. Treat every cycle as a small input contract: source, time, owner, confirmation, and reset. This makes mistakes visible before they cascade through the crew.

## Define one source of range and direction

Choose one observer or approved information source for the current cycle, then state the shared reference point in plain language. The caller owns the final range-and-direction message and includes when it was confirmed. If a second source disagrees, pause the cycle instead of averaging guesses. “Fresh” means recently reconfirmed for the current target state, not merely copied from the previous call.

## Give every crew member one explicit role

Keep roles simple: observer reports change, caller validates and announces the current input, operator repeats it back, and logistics owns supply status. One person may cover two roles in a small crew, but the ownership must remain explicit. The categories shown on the [Foxhole cheats](https://melonity.gg/en/foxhole) page—calculation, transport workflows, notifications, and map awareness—illustrate why artillery is partly an information-flow problem, not one isolated number.

## Treat target updates as expiring information

Every update should carry a short age signal: “confirmed now,” “unchanged since the last cycle,” or “invalid—awaiting a new observation.” The receiver repeats back the changed part, not an entire speech. If the target context changes or the observer loses confidence, invalidate the old call immediately. Silence must never mean “keep using the last value.” It means stop and request a fresh confirmation from the assigned source.

## Keep ammunition logistics in the same loop

A perfect call is useless if the next cycle cannot be supplied. Logistics reports the ready batch, the estimated continuity, and the interruption signal before the crew commits. Avoid vague “we have plenty” messages. Use a simple status the caller can acknowledge: ready for the current cycle, limited after it, or paused for resupply. This keeps timing and supply inside one shared picture instead of two disconnected conversations.

## Reset after every cycle

After the action, the caller names what remains valid and what must be reconfirmed. The observer updates the target state, logistics updates supply, and the operator clears the previous call from working memory. This ten-second reset prevents yesterday’s information—in crew terms, the last cycle—from sneaking into the next one. If nothing changed, say so explicitly; do not make the team infer it.

## The 20-second pre-cycle checklist

- One current observer or source is named.
- The reference point is shared.
- Range and direction carry a fresh confirmation.
- The operator repeats back the call.
- Supply status covers the current cycle.
- Old inputs are cleared or explicitly retained.

When reviewing [cheats for Foxhole](https://melonity.gg/en/foxhole), treat calculators and awareness tools as inputs to this crew process, not replacements for clear calls and fresh data.

## Conclusion

Reliable coordination is boring in the best way: fresh inputs, obvious ownership, short confirmations, and a clean reset. Make that shared rhythm automatic between every cycle at the team level, and stale information has far fewer places to hide.

## FAQ

### What information should be repeated back by the crew?

The current reference point, range, direction, and any changed supply status.

### How quickly does a target call become stale?

As soon as its observed context changes or the source can no longer confirm it.

### Can a calculator replace an observer and caller?

No. It supplies an input; people still own freshness, context, and confirmation.

### Why should ammunition status be part of the firing checklist?

Because a cycle is not ready when its information and supply plans disagree.
