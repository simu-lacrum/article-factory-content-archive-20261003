## Accuracy starts before the shot

Foxhole artillery coordination fails long before any visible result when a correct input arrives late, an old update is treated as fresh, or two crew members use different reference points. The answer is not more chatter. It is a shared information contract: one source, a freshness check, an assigned owner, a repeat-back, and a reset after each cycle. Reliable crews make every input traceable before they act on it.

## Define one source of range and direction

Choose one recognized source for the current range and direction call, then name the crew member who owns it. Every call should identify its reference point and whether the observation is fresh enough for the present cycle. Do not merge numbers from separate observers unless the caller explicitly reconciles them. If a new update arrives, invalidate the previous one aloud. Record the source in the same short format every time. This is a communication rule, not a firing technique: everyone should know which input is current, who confirmed it, and when it expires.

## Give every crew member one explicit role

Separate observation, calculation or calling, operation, and ammunition flow at a high level. One person may cover two roles in a small crew, but each decision still needs a named owner. Say explicitly when one person changes roles, so acknowledgements never go to an empty position. The observer updates context; the caller validates the input; the operator repeats the approved call; logistics reports supply and interruptions. The categories presented on the [Foxhole cheats](https://melonity.gg/en/foxhole) page—calculation, transport automation, notifications, and map awareness—show why artillery accuracy is partly an information-flow problem, not one isolated number.

## Treat target updates as expiring information

A target update is perishable. Attach a timestamp or simple freshness call, repeat it back, and replace it rather than stacking new details onto an old message. Mark the old call invalid before reading the replacement. If the observer loses confidence or the reference changes, the caller should cancel the cycle before another action begins. Avoid vague phrases such as “same place” or “a little over.” They hide which reference is being used. The key question is always: does every role hold the same current input, or is someone acting on a previous state?

## Keep ammunition logistics in the same loop

Supply is part of the information contract. Before a cycle, the logistics role should report what is ready, what is reserved, and what interruption would stop the sequence. Use batch status rather than optimistic guesses, and state when the next update is due. If delivery timing changes, the caller needs that update before promising another cycle. This prevents the crew from validating fresh target information while relying on stale supply assumptions. A short ammunition-status call also helps the next team understand whether a pause comes from observation, coordination, or the supply chain.

## Reset after every cycle

After each cycle, clear the previous approval and ask what changed: reference point, freshness, role ownership, supply status, or interruption state. Do not let silence mean “repeat.” Require a fresh acknowledgement before reopening the loop. A reset creates a clean boundary between two sets of inputs and stops a valid old call from leaking into a new situation. The crew can move quickly once that habit is automatic, because nobody needs to reconstruct whether the last message still applies.

## The 20-second pre-cycle checklist

Confirm six items:

- one reference source is active;
- the update is fresh;
- every role has an owner;
- the caller received a repeat-back;
- ammunition status is confirmed;
- the previous cycle has been reset.

If one check fails, pause the cycle and name the missing owner or stale input. The checklist is short so the whole crew can hear the same state without extra debate.

## Conclusion

Reliable coordination is a clean chain of custody for information. Name the source, owner, timestamp, confirmation, supply state, and reset. Tools may display inputs, but the crew still has to keep every handoff current and shared.

## FAQ

### What information should be repeated back by the crew?

Repeat the active reference, the current approved input, role ownership, and any supply or interruption status that changes the cycle.

### How quickly does a target call become stale?

There is no universal timer. Treat it as stale whenever observation, reference, or target context changes.

### Can a calculator replace an observer and caller?

No. A calculator can present an input or output; people still validate freshness, ownership, and shared understanding.

### Why should ammunition status be part of the firing checklist?

Because a technically valid call is useless when the supply state cannot support the next coordinated cycle.
